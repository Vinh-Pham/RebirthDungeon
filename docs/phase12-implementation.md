# Phase 12: Presentation, accessibility and performance

Status: **Complete for host acceptance (2026-09-15).** Dependencies: 7; relevant feature phases.

## Persistent settings

`scripts/services/settings_service.gd` owns player presentation preferences in
`user://settings.cfg` (ConfigFile): master/music/effects volumes (0..1),
reduced motion, text scale (continuous 1.0–1.4; the panel offers 100/115/130%)
and keyboard bindings for `move_left/right/up/down` and `shell_back`. Missing
or corrupt files fall back to defaults without surfacing errors; every value
is clamped on load. Settings are presentation-only: nothing here reads
session state, draws gameplay RNG or touches the session save. A dedicated
unit fixture proves save/load round trips, corrupt-file fallback, clamps,
InputMap rebinding semantics and AudioServer application.

## Audio

`tools/generate_audio.gd` synthesizes every sound in `assets/audio/`
procedurally — 16-bit mono 22 050 Hz WAVs with deterministic value noise and
exponential envelopes, regenerated byte-stable on demand. All samples are
original repository content; attribution is recorded in
`assets/audio/ATTRIBUTION.md` alongside the SpriteCook art record. Two
seamless music pads (`music_town`, `music_battle`) are seamless by
construction: every voice completes an integer number of cycles per loop and
the chord crossfade envelope is periodic with the loop length.

`default_bus_layout.tres` adds Music and SFX buses under Master;
`scripts/services/audio_service.gd` (a child of the persistent Main — no new
autoload) plays a six-voice SFX pool and one looping music player, applying
settings volumes through `AudioServer`. Main routes accepted domain events
inward (`rolled`/`rerolled` → dice, cross-target `effect` → hit,
`potion_used`/services → heal, `battle_finished` → stings, `enter_dungeon`
and room discovery → door): audio is a pure presentation consumer of
already-accepted results and never influences rules.

## Accessibility

- Reduced motion disables exploration camera damping, the encounter-marker
  pulse and the hero walk bob, and drives the existing battle-stage reduced
  motion path. The battle view's own controls write back through the same
  service, so a preference set in one battle survives everywhere.
- Text/UI scale scales the shell theme base size plus every explicit label
  size (HUD hint, battle view via its existing setter). The persisted value
  stays continuous so the battle view's ± buttons keep their Phase 5
  contract; the settings panel offers the authored 100/115/130% options.
- Key rebinding replaces only listed key events; joystick bindings assigned
  by `shell_input_map` survive, and Reset restores the authored defaults.
- Status information remains text-first: HP/MP/SP and enemy blocks carry
  numeric labels next to their bars, and statuses render as name/source/
  duration text in the inspection sheet — no cue relies on color alone.
- The Settings surface is reachable from the title screen and the exploration
  HUD; opening it from exploration freezes the world and closing restores
  input ownership exactly like the other modal panels. Escape closes.

## Development-only surfaces

The session/revision telemetry status row and the town's direct dungeon
fixture are hidden unless the build is a debug build (`development_enabled`),
and the former release-blocking guards on chart navigation were removed so
the title screen's Start Game is the real release path. The intentional
negative fixture now asserts the release behavior: development disabled can
still start from the title, reaches town, and never exposes the development
dungeon fixture.

## Performance

Measured with the editor runtime profiler (Beckett performance monitors)
across town, generated dungeon traversal and battle on the pinned desktop
host. Recorded results and budgets live in
[evidence](evidence/phase12/README.md); no optimization was applied without a
measured regression. Loading of required resources stays inside the Phase 1
guarded loading screen; asset additions (~0.8 MB of WAV) ship in all five
export packs (see verify logs).
