## Domain and persistence fixtures

Run Lester with injected time, storage and random inputs. Keep expected behaviors independent of implementation details.

- Combat: fixed order and seeded ties; one turn per living actor; every mastery rank's fractional costs/recovery; one item then a main action; Wait eligibility; shared preview formulas; critical/multi-hit/counter handling; start/end status boundaries; immediate termination.
- Rejection/retry: unchanged committed inputs, events and RNG on invalid/stale commands; duplicate operation handling; no duplicate turn start, enemy action, reward, chest choice, quest claim or page consumption after restart.
- Economy/inventory: purchases, 25% sale values, repairs, equipment/race restrictions, full transfers, bank ownership, capacity/overflow and failure rollback. Footprint fragmentation and exchanges arrive with milestone 6.
- Progression: EXP thresholds/cap, fractional growth, AP, Saturday-noon America/Los_Angeles boundaries, DST/offline catch-up/rollback, rebirth cooldown bands and preserved progression.
- Saves: corrupt newest/previous slots, unsupported future formats, interrupted index writes, uncertain write results, correct generation choice, content/story migration, character switching and no defaulting corrupt profiles.
- World: at least **1,000 deterministic seeds** with seven connected rooms, legal spawns, three required encounters, reachable optional rooms and boss progression. Optional-room completion must not become a hidden gate requirement.
- Later systems: title ownership/stat removal, enchant outcomes and retries, run-banked quest evidence, RP isolation and archive retention when each feature is implemented.

Use the actual pinned RNG/DefSave/Quest/Ink integrations for continuation and rollback tests in the engine test collection. A/B tests must simulate interruption, not merely mock a successful save return.

## Desktop acceptance journey

Create → move through Town1 → use services → enter Alby → use item and battle actions → collect loot → defeat boss → choose exactly one of five chests → Continue to town → quit → resume.

Exercise name/race/talent/20-character limits; normalized diagonal movement; camera-aware click-to-move; blocked destinations; keyboard route cancellation; NPC approach; gates; no motion behind panels or after focus loss; no GUI click-through; busy/rapid-click guards; independent music/effects volume; reduced motion; defeat and confirmed abandonment. Quit/restart after every durable boundary, including optional item, enemy action, quest/dialogue choice, loot selection, chest choice and return.

Capture Title/creation, HUD, town, battle, inventory, dialogue and treasure at **1280×720 and 1024×768**, including high DPI, enlarged HUD and long text. Check fit/letterbox choice, text input, fonts, draw order, visible controls and bundled assets. Use real mouse/keyboard input, an engine harness or desktop automation, and debug-only observable state. Defold GUI has no browser DOM locator contract.

First-slice panels pause world controls and updates. Later draggable nonblocking windows need their own focus/gesture checks before enabling that policy. HTML5 is a separate future pass for storage, focus, scaling and native-extension support.
